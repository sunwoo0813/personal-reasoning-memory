# Evidence Grounding v2 — 구현 및 반복 E2E 검증

작성일: 2026-11-20 (Asia/Seoul)

최종 코드의 동일 조건 3회 반복 중 **2회 완료**했다. 완료 Run의 49개 객체, 101개 근거는 모두 정확한 원문 구간과 일치했다. 이 결과는 의미적 진실이나 일반적인 안정성을 입증하지 않는다.

## 1. 기존 실패의 정확한 원인

구 방식은 모델이 quote를 재작성하고 오류 시 Episode 전체를 다시 생성했다. 2026-11-19 EP01은 세 응답에서 E16의 `합리적이야.`를 `합리적이다.`로 바꿨다. 마지막에는 E19의 `메인 데이터`에서 공백도 삭제했다. 첫 응답에는 근거가 빈 객체 2개가 있었다. 원문 검증 거부 자체는 옳았지만, 정상 객체까지 바꾸는 전체 재생성이 안정적으로 복구하지 못했다.

## 2. 선택한 설계와 대안

직접 인용 생성 대신 코드가 원문 문단·구간을 식별하고 모델이 evidence_id를 선택한다. 숫자 offset을 모델이 추측하는 방식은 채택하지 않았다. 코드는 이벤트·필드·UTF-16 반열린 위치 [start,end)·원문 문자열을 확인한 뒤 인용을 복원한다. 공백·어미·문장부호를 수정한 문자열을 quote로 저장하지 않는다. 동일 문장도 구간별 ID와 위치로 구분한다.

존재하는 ID를 잘못 선택할 수 있으므로 화자 규칙을 출력 스키마와 기존 검증기에 적용하고, 별도 모델 호출로 근거 관련성을 확인한다. 질문은 실제 질문 발화로, 가설은 실제 가설 제시로 뒷받침할 수 있다. 답이나 가설의 진실성을 필수로 요구하지 않는다. 반대·무관한 해석은 unsupported/uncertain으로 남긴다. 이 모델 판단은 model_supported이며 semantic_verification은 not_verified로 유지한다.

실패 슬롯만 최대 2라운드 교정한다. 정상 객체는 고정하고 실패 객체를 삭제해 성공 처리하지 않는다. 미해결 객체가 하나라도 있으면 전체 Episode·Run을 완료하지 않는다. 완성 전 감사 JSON은 정상 객체 체크포인트와 구분한다.

## 3. 변경 파일 및 주요 로직

- lib/evidence-grounding.js: 원문 ID·위치, 스키마, 관련성 검토, 객체별 오류/교정, 감사·사용량, 체크포인트 검증
- lib/analysis.js: v2 기본 경로, 입력 카탈로그 전달, 기존 legacy-v1 경로와 구 체크포인트 호환. type·speaker·결정/가설/Open Question 정책 유지
- scripts/analyze.mjs: 기존 analysis_steps JSON에 감사 기록. 성공한 완전한 결과만 기존 finish RPC로 최종 저장
- tests/evidence-grounding.test.mjs, tests/analysis-db.test.mjs, tests/analysis.test.mjs: 신규 검증·기존 경로·PostgreSQL 호환성
- scripts/evaluate-grounding-v2.mjs, scripts/summarize-grounding-v2.mjs: DB 읽기 전용 반복 평가와 집계
- 기존 E2E 평가 스크립트는 legacy-v1을 명시해 과거 비교 정책을 보존
- docs/evidence-grounding-v2.md, README.md: 설계·용량·재개 제한 문서화

DB 스키마, 기존 세션·이벤트·분석 Run은 변경하지 않았다. 완성 체크포인트는 재검증해 재사용하고, 중단된 v2 감사는 정상 결과로 재사용하거나 교정 예산을 초기화하지 않는다. 중단된 Episode는 새 Run이 필요하다.

## 4. 자동 테스트

기존 64개와 신규 20개, 총 **84개 테스트 통과**. 빌드와 git diff --check도 통과했다. 어미·공백 변형 거부, 혼합 Unicode/이모지·UTF-16, 반복 문장, 잘못된 이벤트·필드·ID, 복수 근거, 일부 실패만 교정, 환각 근거, 문자열 일치/반대 해석, 불확실 검토, 스키마 오류와 제한 재시도, 실패 결과 미저장, 신·구 체크포인트 재개를 포함한다. PostgreSQL jsonb 키 재배열 후의 해시 검증·재개와 기존 원문 일치 트랜잭션도 확인했다. 의미 검토 테스트의 모의 응답은 아래 실제 모델 실험과 구분한다.

## 6. 구 방식과 완료·인용 비교

| 범위 | 구 방식 2026-11-19 | 최종 evidence-v2 |
|---|---|---|
| 같은 2개 Episode 전체 실행 완료 | 0/1 (과거 한 번) | 2/3 (최종 코드 고정 반복) |
| 전체 완료 결과의 수락 객체 | 0 | 49 |
| 완료 결과의 원문 인용 | 전체 결과 없음 | 101/101 일치 |
| 거부된 구 방식 후보의 문자열 진단 | 36/40 일치, 빈 근거 2객체 별도 | 모델 생성 quote를 저장하지 않음; 의미·화자 실패는 계속 거부 |
| 기록된 구 방식 입력/출력/총 토큰 | 80232 / 7632 / 87864 (실패한 전체 실행) | 위 반복별 표 참조; 성공 결과와 추가 검토 비용 포함 |

구 방식의 EP02 독립 성공 6객체를 구 방식 전체 실행의 성공으로 합산하지 않았다. 과거 1회 대조와 새 반복은 표본 크기·실행 시점이 달라 통계적 안정성 개선이나 단독 인과 효과로 해석할 수 없다. 문자열 일치 100%는 원문에서 잘라내고 검증한 결과의 보장이지 해석의 정확도 100%가 아니다.

초기 개발 실험 3회는 1회 완료였고, 모든 성공·실패 기록은 output/evidence-grounding-v2-2026-11-20에 보존했다. 화자 제약을 스키마에 반영하고, 질문·가설의 기록에 답변·진실성까지 요구하던 모델 검토 지침을 보완한 뒤 최종 코드를 고정해 위 3회를 다시 실행했다. 서로 다른 코드의 실험을 최종 완료율 분모에 섞지 않았으며 실패 이력을 숨기지 않았다.

## 7. 남은 한계

- 관련성 모델도 오판할 수 있다. not_verified 표시를 유지하며 확정적 의미 검증으로 발표하지 않는다.
- 원문 ID가 존재해도 잘못된 구간을 고를 수 있다. 스키마는 화자·출처 범위만 제한하고 해석의 정확성을 보장하지 않는다.
- 인용 단위가 문구보다 넓어 불필요한 주변 문장을 포함할 수 있다. 원문을 임의로 다듬지 않는다.
- 검토와 국소 교정은 비용·지연을 추가하며 여전히 실패할 수 있다. 실패 슬롯을 삭제하거나 부분 성공을 complete로 만들지 않는다.
- 사용자 가설 누락, 검색어/Open Question 혼동, 판단 변화의 분류는 이번에 바꾸지 않았다. 이들의 개선을 주장하지 않는다.
- 한 세션의 작은 반복 표본이고 독립 사용자 평가가 아니다. 일반적인 안정성에는 다른 길이·문서·대화·오류 분포의 추가 평가가 필요하다.
- 850개 구간과 기존 입력 크기 한도가 있다. 미완료 v2 감사의 자동 재개는 제한하며 새 Run이 필요하다.

## 재현

```sh
node scripts/evaluate-grounding-v2.mjs output/evidence-grounding-v2-new-check 3
node scripts/summarize-grounding-v2.mjs output/evidence-grounding-v2-new-check
```

새 디렉터리를 지정해야 한다. 각 Run의 analysis-result.json, call-*.json, audit-trace.jsonl, checkpoint-ep*.json에 원시 응답·오류·사용량·완료 객체를 보존한다. source-snapshot.json과 protocol.json으로 원본·정책·코드 해시를 확인할 수 있다. Secret은 출력하지 않는다.
