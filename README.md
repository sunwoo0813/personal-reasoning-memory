# PRM 수집기 (개발 중)

이 프로젝트는 본인 PC의 Chrome에서 발생하는 활동을 수집해 전용 Supabase 프로젝트에 보관하는 로컬 개발용 구현입니다. 로그인과 다중 사용자 격리는 제공하지 않습니다. **인터넷이나 공유 네트워크에 공개하지 마세요.**

## 설정

1. 기존 서비스와 분리된 전용 Supabase 프로젝트를 준비합니다.
2. Supabase SQL Editor에서 `db/schema.sql` 내용을 실행합니다. 기존 프로젝트에는 적용하지 마세요.
3. `.env.example`을 `.env.local`로 복사하고 전용 프로젝트 URL과 서버 전용 Secret API Key를 입력합니다. 이 키를 채팅이나 Git에 올리지 마세요.
4. `npm install`, `npm run dev`를 실행하고 Chrome에서 `http://localhost:3000`을 엽니다.
5. Chrome의 `chrome://extensions`에서 개발자 모드를 켜고 **압축해제된 확장 프로그램을 로드**하여 이 프로젝트의 `extension` 폴더를 선택합니다. 설치 후 웹사이트를 새로고침합니다.
6. 프로젝트를 만들고 작업을 시작합니다. 종료 시 웹사이트를 열린 상태로 유지해 대기열 전송을 완료합니다.

확장 프로그램을 새로고침한 뒤 이미 열려 있던 HTTPS 탭에 수집 스크립트가 없으면, 세션 중 해당 탭이 활성화될 때 연결을 시도합니다. 이를 위해 `scripting` 권한을 사용합니다. Chrome 내부 페이지, 권한이 제한된 페이지와 민감 정보 보호 조건에 해당하는 페이지는 수집되지 않을 수 있습니다. 확장 프로그램 팝업에서 연결 실패·제외 횟수를 확인할 수 있습니다.

기본 포트는 3000입니다. 다른 프로젝트와 겹치면 Git에 포함되지 않는 `.env.local`에 `PRM_PORT=3001`을 추가하세요. 이 설정은 본인 PC에만 적용되며, 확장 프로그램은 3000과 3001을 지원합니다. 변경 후 개발 서버를 다시 실행하세요.

## 알려진 제한

- 수집·저장·분석의 자동 시험과 실제 API 호출은 검증 기록에 구분하여 남깁니다. 지원 사이트·브라우저 중단·대용량 기록의 통합 검증은 계속 필요합니다.
- 웹사이트가 닫히거나 서버가 중지되면 대기 이벤트는 확장 프로그램에 남고 웹사이트를 다시 열었을 때 전송을 재시도합니다.
- ChatGPT 화면 구조가 변경되면 대화가 누락될 수 있습니다. 메시지 식별자가 없으면 DOM 임시 식별자를 사용해 부분 수집으로 기록하며 화면 재구성 시 중복될 수 있습니다. 질문·답변을 확보한 경우 `complete`로 표시할 수 있으며, 답변 완료 관찰 여부는 `completion_observed`로 별도 보존합니다. 재생성·수정·분기와 장시간 스트리밍은 추가 검증이 필요합니다.
- 기본 제외 도메인과 비밀번호·결제 입력 폼 탐지는 모든 민감한 사이트·개인 메시지·민감정보를 완벽히 식별하지 못합니다. 사용자는 확장 프로그램에서 민감한 사이트를 제외하거나 일시 중지해야 합니다.
- 일반 페이지 본문은 접근 가능한 `article`·`main`·`role=main`의 표시 텍스트만 최대 60,000자 수집합니다. 메뉴·광고 영역·폼·입력창·숨겨진 요소는 제외하고, 본문이 없거나 추출에 실패하면 방문 정보만 남깁니다. ChatGPT는 질문·답변 수집 경로를 사용합니다. 이미지 PDF, Chrome 내부 페이지, iframe 및 동적 앱은 완전한 본문 수집이 보장되지 않습니다.
- 서비스 워커 중단, 저장 용량 초과, 대량 이벤트, 다중 창, 응답 중 새로고침과 세션 종료 경합은 통합 시험이 필요합니다.

## 본문 스냅샷

방문을 마칠 때의 주요 본문과 수집 시각·추출기 버전을 이벤트에 보존합니다. 서버에서 길이 제한을 다시 확인하고 본문의 SHA-256 해시·저장 길이를 기록합니다. 화면의 **저장된 본문 보기**에서 당시 내용을 확인할 수 있습니다. 과거에 본문 없이 저장한 이벤트는 자동 복원하지 않습니다. 확장 프로그램 파일을 변경한 뒤에는 `chrome://extensions`에서 새로고침하고 기존 웹 탭도 새로고침하세요.

## 세션 분석 — 분할과 사고 요소 추출

이 단계는 Episode 분할과 사고 요소 추출까지 구현합니다. 관계·인과 분석, 의미상 근거 검증, Gap·Trail 통합과 사용자 수정 저장은 후속 단계입니다. `quote_matched`는 원문 인용의 일치만 뜻하며 의미적 검증 완료를 뜻하지 않습니다.

1. 기존 전용 DB에서 `db/analysis.sql`을 한 번 실행합니다. 기존 원본은 유지하고 분석 테이블과 함수를 추가합니다. 새 DB에서는 `db/schema.sql`을 먼저 실행합니다.
2. `.env.local`에 서버 전용 `OPENAI_API_KEY`를 설정합니다. 모델 기본값은 제안서의 `gpt-5-mini`이며 `PRM_ANALYSIS_MODEL`로 변경할 수 있습니다.
3. 개발 서버를 다시 실행하고, 별도 터미널에서 `npm run analyze`로 분석 워커를 실행합니다. 작업 하나만 처리하려면 `npm run analyze -- --once`를 사용합니다.
4. 종료·동기화 완료된 세션에서 **활동 보기 → 생각의 흐름 → 분석하기**를 선택합니다. 분석은 작업 중 수집과 분리된 백그라운드 워커에서 수행됩니다.
5. 완료 결과에서 각 사고 요소의 인용문과 **저장된 원문 확인**을 비교합니다. 재분석은 새 Run으로 저장하며 이전 결과를 덮어쓰지 않습니다.

Run 생성 시 원본 이벤트 목록과 전체 내용을 스냅샷으로 고정합니다. Episode 배정의 누락·중복·순서와 인용문의 실제 존재, 발화 주체를 검사합니다. 사용자 결정은 질문 필드의 사용자 발언에 연결해야 합니다. 자료·AI 제안을 사용자 동의로 간주하지 않습니다. 웹페이지와 대화는 모델의 지시가 아닌 비신뢰 입력으로 처리하며 모델에 외부 도구를 제공하지 않습니다.

분석 단계별 결과·토큰 사용량을 체크포인트로 저장합니다. 중단된 워커의 10분 이상 갱신되지 않은 작업은 다른 워커가 이어받고 저장된 단계는 재사용합니다. 실패한 Run은 이력에 남으며 **다시 분석**으로 새 Run을 요청할 수 있습니다. 1회 입력 240,000자·최대 30 Episode를 초과하면 명시적으로 실패하며 원문을 조용히 잘라 분석하지 않습니다.

## 검증

- `npm test`: 본문 제외·잘림, 기존 수집 회귀, 분할 누락·중복·잘못된 인용과 발화 주체, 로컬 PostgreSQL 엔진의 스냅샷·트랜잭션·Run 이력 시험.
- `tests/fixtures/research-session.json`: 실제 개인 대화와 구분된 합성 조사 세션.
- `docs/verification/extraction-example.json`: 합성 세션으로 실제 모델을 호출한 결과. 모의 모델 테스트와 구분합니다.
