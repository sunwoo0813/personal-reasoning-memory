# Episode 분할 정책 purpose-v2

외부 결과 형식은 `extraction-v1`을 유지한다. 이번 변경은 Episode 분할과 그 검증에만 적용되며, Relationship Analysis나 원본 이벤트 수정은 포함하지 않는다.

## 확인한 원인과 시간 필드

`extension/worker.js`의 `append()`가 이벤트 확정 시 `client_seq`를 증가시킨다. 페이지는 `endPage()`, 대화는 `finalizeChat()`에서 추가되므로, 순번은 사용자 행동 시작 시각순이 아니다.

| 필드 | 현재 코드의 의미 | 사용 시 제한 |
| --- | --- | --- |
| `client_seq` | 확정된 이벤트가 수집 대기열에 추가된 순서 | 변경·재정렬하지 않는다. |
| `started_at` | 페이지 활성 시작 관찰, 검색·복사 메시지 수신 관찰, 또는 대화의 `submittedAt`/DOM 관찰 시각 | 대화의 시작 시각 출처를 구분하는 필드는 저장되지 않는다. 검증된 실제 메시지 시각으로 단정하지 않는다. |
| `ended_at` | 페이지 종료 관찰, 대화의 완료 관찰 또는 강제 확정 시각 | `completion_observed=false`라면 실제 답변 완료 시각이 아니다. |
| `received_at` | 서버에서 이벤트를 저장한 시각 | 사용자 행동 시각이 아니다. 클라이언트와 서버의 시계 차이가 있을 수 있다. |

실제 22개 기록에서 E09는 `started_at=2026-11-18T09:37:02.210Z`, `ended_at=09:43:29.500Z`, `client_seq=9`였다. E01의 관찰 구간은 `09:36:02.444Z`부터 `09:37:02.325Z`까지다. E09의 시작 관찰은 E01 구간 안에 있지만 E04~E08 뒤에 확정됐다. 기존 모델 입력은 종료·수신 시각과 이 의미를 제공하지 않았다.

기존 분할 프롬프트는 조사 질문·목적을 짧게 언급했지만, `validateSegments()`는 원본 배정의 누락·중복·순서와 설명 필드만 검사했다. E20의 새로운 결정 문제를 놓친 결과도 구조적으로는 유효했다.

## 변경한 흐름

1. 별도 `review_session_purposes` 모델 호출에서 실제 사용자 질문마다 조사 목적과 관계를 검토한다. 첫 질문, 같은 목적의 후속 질문, 독립적인 새 목적, 판단 불확실을 구분한다. 모든 질문이 한 번씩 포함되고 인용이 해당 사용자 질문의 정확한 부분 문자열인지 검사한다. 이 호출에는 답변·웹 본문을 제공하지 않고 사용자 질문·검색어와 관찰 메타데이터만 제공한다.
2. 수집된 시작 관찰이 이전 ChatGPT 페이지의 관찰 구간에 들어가고 탭과 대화 식별이 맞는 경우, 이전 맥락 후보를 제공한다. 초기 `/`·임시 대화 URL에서 정식 대화 URL로 전환되는 수집기의 동작도 고려한다. 다른 확정 대화, 다른 탭, 없거나 잘못된 시각은 연결하지 않는다. 시간 중첩만으로 묶지 않고, 독립 검토가 실제 질문과 중간 활동의 같은 목적을 확인한 후보만 사용한다.
3. 분할 모델은 원래 순번에서 각 구간의 끝 위치만 선택한다. 사용자의 목적 변화가 기술·웹사이트·조사 단계의 변화보다 우선한다. 검토에서 도출된 연속 맥락 안의 경계는 출력 스키마의 허용 위치에서 제외하고, 새 목적 앞의 필수 경계는 별도로 검증한다. 원본에서 벗어난 후보를 사후에 강제 수정하지 않는다.
4. 새 목적의 질문 앞에 경계가 있는지, 후속 질문·검토된 지연 대화 맥락을 불필요하게 나누지 않았는지 추가 검사한다. 본문 없는 방문 정보만으로 독립 구간을 만드는 결과도 거부한다. 전부 본문 없는 세션은 중립적인 방문 기록 구간 하나로 유지하고 사고 요소는 생성하지 않는다.
5. 검증 실패는 이유를 전달해 최대 두 번 교정한다. 여전히 실패하면 실패 상태를 유지한다. 강제로 경계를 수정하거나 검증을 통과하지 못한 결과를 완료 처리하지 않는다.

검색 → 자료 방문 → ChatGPT 복귀, 가설 수정, 반론, 최종 선택과 그 이유의 정리는 같은 목적의 연속일 수 있다. 반대로 같은 프로젝트·대화에서도 독립적인 의사결정이 시작되면 새 구간이 된다. 키워드 목록이나 특정 E번호에 대한 분할 규칙은 없다.

## 저장·체크포인트 호환성

`prm_create_analysis_run()`은 `client_seq`순으로 고정 스냅샷을 만들고, `prm_finish_analysis_run()`은 구간별 이벤트를 펼친 목록이 그 순서와 일치해야 저장한다. 이 제약과 `db/analysis.sql`은 그대로 유지한다.

새 분할 체크포인트의 `result.segmentation_policy`에는 `purpose-v2`, 입력 해시, 독립적인 목적 검토 결과를 보존한다. 기존 JSON 컬럼을 사용하므로 스키마 변경은 없다. 검토 호출과 분할 교정에 사용한 토큰은 분할 단계 사용량에 포함된다.

새 체크포인트를 재개할 때 정책 버전·입력 해시·의미 경계 제약을 다시 확인한다. 구 버전 체크포인트는 기존 분할을 그대로 재개하며 새 검토를 소급 적용하지 않는다. 이미 저장된 분할·추출 체크포인트는 재저장하지 않는다. 개선 정책은 체크포인트가 없는 새 Run에서만 적용된다.

## 기존 22개 스냅샷으로 DB를 수정하지 않고 재검증

기존 Run 생성·완료 RPC는 `sessions.analysis_status`도 수정한다. 기존 세션·Run의 수정까지 금지된 검증에서는 다음 읽기 전용 도구를 사용한다.

```sh
node scripts/revalidate-segmentation.mjs \
  --source-run c4bbd6f5-77d4-4a55-a5b3-7d3f1c410061 \
  --output output/segmentation/purpose-v2-new-check.json
```

`.env.local`의 기존 서버 연결 설정과 `OPENAI_API_KEY`를 사용하며 키를 출력하지 않는다. 지정한 완료 Run의 스냅샷을 페이지 단위로 읽고, 같은 모델로 **분할만** 수행한다. 새 UUID가 있는 로컬 검증 Run과 이전/이후 구간·모델 응답 이력을 JSON에 저장한다. 기존 출력 파일은 덮어쓰지 않으므로 실행마다 새 경로를 지정한다. DB에 신규 분석 Run을 등록하거나 원본 세션·이벤트·기존 Run·체크포인트를 수정하지 않는다. 전후 상태 해시로 읽은 원본의 불변성을 확인한다. 외부 프로세스가 이 원본 상태를 바꿔도 검증 실패로 기록한다. 모델 호출 비용은 발생한다.

일반 앱 분석은 기존과 같이 `npm run analyze`로 수정된 워커를 실행한 뒤 **다시 분석**한다. 이 경로는 별도 DB Run을 만들고 기존 결과는 보존하지만, 기존 설계대로 세션의 분석 상태는 갱신한다. 엄격한 읽기 전용 재검증에는 위 명령을 사용한다. 실행 중인 워커는 새 코드를 반영하려면 재시작해야 한다.

## 검증 범위와 한계

`tests/segmentation.test.mjs`는 지연 확정 대화, 검색·웹 조사·복귀, 명시적 새 목적, 후속 질문, 가설 수정·반론, 본문 없는 방문, 한 대화 안의 독립 목적, 시각 부재·잘못된 대화 연결, 누락·중복·순서 거부, 제한된 교정 실패, 신·구 체크포인트 재개를 다룬다. 기존 추출 테스트와 PostgreSQL 저장·롤백 테스트도 유지한다.

이 테스트의 의미 판단은 모의 모델 응답으로 제어되므로 실제 모델의 일반적인 의미 판별 정확도를 증명하지 않는다. 실제 E2E 비교도 한 사례의 결과일 뿐이다. 독립적인 목적 검토가 명시적 전환을 놓치거나 후속 질문을 잘못 분류할 수 있고, 그 오판은 구조 검증만으로 모두 찾을 수 없다. 별도 검토 호출과 교정은 지연·비용을 추가한다.

원본 순서를 유지하는 연속 구간 제약상, 뒤늦은 대화를 과거 맥락에 포함하려면 중간 기록도 같은 구간에 포함해야 한다. 그 사이 독립적인 목적 전환이 있으면 과거로 연결하지 않는다. 원래 행동 시각의 출처가 불명확하거나 메타데이터만 있을 때는 맥락을 확정하지 않는다. 과거 방문에 없던 본문이나 사용자 의도를 복원하지 않는다.

## 2026-11-19 실제 세션 비교

최종 코드로 같은 `gpt-5-mini` 모델과 기존 22개 스냅샷을 사용해 분할만 재검증했다. 완료된 로컬 검증 Run은 `output/segmentation/purpose-v2-comparison-2026-11-19-4.json`에 있다.

| 항목 | 기존 결과 | 개선 결과 |
| --- | --- | --- |
| Episode 배정 | E01–E03 / E04–E08 / E09–E16 / E17–E22 | E01–E19 / E20–E22 |
| 최초 질문 E09 | 관련 초기 방문·자료 조사와 분리 | 초기 맥락·조사·가설 수정·저장 방식 결정과 같은 구간 |
| 새 의사결정 E20 | 저장 방식 결정과 회원가입 검토를 혼합 | E20 앞에서 경계를 만들고 회원가입 검토·보류를 별도 구간으로 배정 |
| 무결성 | 원본 배정 구조는 유효했음 | 이벤트 22개 원래 순서·정확히 한 번 배정, 읽은 원본 상태의 전후 해시 일치 |

최종 실행의 목적 검토·분할 호출은 각각 한 번이었으며 교정 호출은 없었다. 개발 중 실패한 검증 Run도 별도 파일로 보존했다. 이 한 번의 성공을 일반적인 분할 정확도 향상으로 해석하지 않는다. 이 비교에서는 Reasoning Object를 다시 추출하지 않았으며, 개선 결과를 DB나 기존 PDF에 반영하지 않았다.

최종 자동 검증: `npm test` 64개 통과. 기존 PostgreSQL 시험은 새 정책 체크포인트 저장·완료와 잘못된 배정의 트랜잭션 롤백, 기존 Run·이벤트 보존을 추가 확인한다. 의미 평가에 모의 응답을 쓰는 회귀 테스트와 위 실제 모델 실행은 구분한다.
