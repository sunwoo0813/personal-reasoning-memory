# 작업 회고 — summary-v1 계약 / summary-policy-v2 정책

## 데이터 경계

분할·추출 정책을 변경하지 않는다. 회고 입력은 완료된 Run의 Episode, 사고 요소 ID·유형·발화 주체·내용과 원문 인용이다. 전체 원본이나 외부 자료를 새로 가져오지 않는다. 참조 ID는 해당 Run 안에서만 유효하며 모든 요약 문장에 연결한다. 결정은 question 필드에 명시된 사용자 decision만 참조한다. 남은 질문은 question 필드에 있는 사용자 question/open_question 중 현재 보류 상태로 검토된 것만 참조한다. query 필드만 근거로 가진 검색어는 남은 질문으로 사용할 수 없다. 없는 항목은 비워 두며 다음 작업은 별도의 AI 제안이다.

결과는 `overview`(최대 1), `topics`(5), `decisions`(5), `open_questions`(5), `suggestions`(3) 배열이다. 각 항목은 `{ text, object_ids }`다. 문장은 최대 500자, 참조는 1~20개로 제한한다. 참조 중복은 런타임에서 거부한다. 사고 요소가 없는 분석은 모델 호출 없이 빈 배열로 완료한다. 입력 또는 검토 입력이 24만 자를 넘으면 자르지 않고 실패한다.

새 요약은 내부 정책 `summary-policy-v2`를 사용한다. 먼저 모든 직접 사용자 질문을 `open / resolved / historical / uncertain`으로 검토한다. 명시적 보류만 open으로 취급하고, resolved에는 원래 질문 외에 후속 사용자 발언이 필요하다. 분석 입력 위치가 있으면 실제 후속 발언인지도 검사한다. 다른 결정을 했다는 이유로 관련 위험 전체의 해결을 추정하지 않는다. 위치가 없으면 시간 순서를 추정하지 않는다.

검토된 최신 open 질문 최대 5개를 요약에 포함하고 가장 최근 질문을 첫 작업 제안의 직접 근거로 사용한다. 첫 제안은 그 판단을 진전시키는 구체적인 확인 작업이어야 한다. 개요도 사용자 결정·보류를 주장할 때 해당 사용자 객체를 직접 인용한다. 조사 주제와 명시적 미해결 상태는 분리한다.

생성 이후 항목별로 선택된 근거와 모든 주장의 관련성·귀속·확정 표현을 검토한다. 각 slot에 `supported / unsupported / uncertain`과 사유를 받으며 누락·중복 검토는 실패한다. 다른 곳에 있는 사용자 원문은 현재 항목에 빠진 직접 근거를 대신하지 않는다. 형식이 유효한 후보에서 실패한 slot만 최대 1회 교정한다. 통과한 slot은 해시로 고정하고 재검토·재생성하지 않는다. 삭제나 통과 항목 변경으로 실패를 숨길 수 없다. 개요·필수 질문·첫 제안·조사 주제가 빠진 경우 명시적인 누락 slot을 교정하도록 한다. 루트 배열 형식 자체가 잘못된 경우에만 추가 생성 1회를 허용한다. 미해결 오류가 있으면 전체 요약은 실패하며 추출 결과는 유지한다.

모델에는 입력 범위 안에서만 유효한 짧은 O1, O2 ID를 전달하고 저장 전에 원래 UUID로 복원한다. 원문 문자열은 변환하지 않는다. 입력·후보 해시와 정책을 체크포인트로 묶는다. 모델 검토는 객관적인 의미 검증을 뜻하지 않으며 상태 판단과 관련성의 오판 가능성이 남는다.

## DB 적용과 호환성

기존 전용 프로젝트에서 `db/analysis.sql` 뒤에 `db/summary.sql`을 실행한다. 기존 분석 설정을 다시 실행할 필요는 없다. 별도 Supabase CLI 마이그레이션 관리 대신 기존 저장소의 명시적인 SQL 설치 절차를 따른다.

`analysis_summary_jobs`는 Run당 한 행이다. `queued / processing / complete / failed` 상태와 결과, 체크포인트, 사용량, 오류, 실행 소유자와 heartbeat를 보존한다. RLS를 활성화하고 anon/authenticated의 테이블·함수 접근을 차단한다. 서버의 service_role만 사용한다.

Run이 complete로 전이될 때 트리거가 같은 트랜잭션에서 작업을 등록한다. 이전 완료 Run은 자동 등록하지 않는다. `prm_request_summary`는 완료 Run만 허용하고 활성·완료 작업 요청에는 같은 행을 반환한다. 실패 작업 재요청 시 생성 체크포인트는 초기화하고 누적 사용량은 유지한다. 분석·원본은 변경하지 않는다. SQL의 version 제약과 외부 result 형식은 summary-v1 그대로이며 추가 SQL 적용은 필요 없다. 기존 완료 요약을 자동으로 덮어쓰지 않는다. 기존 진행 중 체크포인트는 legacy 정책으로 재개하고, 체크포인트가 없는 새 작업부터 새 정책을 적용한다.

`prm_claim_summary`는 행 잠금과 SKIP LOCKED로 한 작업을 가져오며 10분 이상 heartbeat가 없는 작업을 회수한다. 워커는 모든 쓰기를 현재 worker_id와 processing 상태에 한정한다. 소유권을 잃은 워커는 결과·실패를 덮어쓰지 못한다. 모델 호출 전 heartbeat를 갱신한다.

체크포인트는 입력 해시·정책 버전과 각 생성 후보·검토·오류, 확인된 사용량을 보존한다. 재개 시 입력 일치를 검사하고 저장된 호출은 재사용한다. 응답을 받기 전에 프로세스가 종료된 호출은 체크포인트로 복원할 수 없으며 해당 호출의 사용량도 알 수 없다.

## HTTP 인터페이스

- `GET /api/sessions/:id/analysis`: 기존 응답에 `summary_available`과 각 Run의 `summary`를 추가한다. summary는 `run_id, version, status, result, error, created_at, completed_at`과 허용된 `progress.stage`만 공개한다. progress는 JSON 경로로 선택하며 내부 후보와 사유는 읽기 응답에 포함하지 않는다. 체크포인트·내부 검토 응답·작업 소유자는 노출하지 않는다. 요약 테이블 미적용 시 `summary_available: false`로 기존 분석을 반환한다.
- `POST /api/analysis/:runId/summary`: 완료 Run의 최초 요약 또는 실패한 요약만 요청한다. 활성 작업과 완료 결과는 그대로 반환한다. 분석 워커가 처리하며 HTTP 요청에서 모델을 호출하지 않는다.
- `GET /api/analysis/:runId/source/:eventId`: 기존 분석 스냅샷 API를 재사용한다.

## 화면과 검증

900px 초과에서는 240px 세션 탐색과 넓은 상세 화면을, 좁은 화면에서는 상단 세션 선택기를 사용한다. 화면 상태는 세션별로 분리하고 이전 조회·원문 응답을 취소한다. 진행 중 분석·요약은 3초마다 갱신한다. 완료 후 사용자가 선택한 탭을 강제로 바꾸지 않는다. 세션 제목·탭은 읽는 동안 고정하며 탭별 검색과 스크롤 위치를 보존한다. 회고로 돌아가기 동작을 제공한다. 요약 대기 중에는 사용자 상태 검토 → 회고 작성 → 항목별 근거 검토 → 필요한 항목 교정 단계를 표시한다.

회고 → 주제별 카드 → 사고 요소 → 근거 → 원문 패널 순서로 탐색한다. 요약 화면은 Apple 디자인 참조의 카드 형식으로 결정·남은 질문·전체 회고·조사 주제·AI 제안을 구분한다. 요약 항목의 관련 기록 버튼은 표시하지 않으며, 원문 확인은 아래 주제별 사고 요소의 근거에서 제공한다. 원문 패널은 같은 필드의 정확한 인용 일치를 모두 강조하며 첫 위치로 이동한다. 원문에서 활동 기록으로 이동하면 필터를 초기화하고 해당 활동을 펼친다. 일반 기록의 시작 시각 정렬과 분석 입력의 원본 순서는 별개이며 변경하지 않는다.

검증은 유닛 테스트, PGlite 트랜잭션·권한·복구 테스트, JSDOM에서 실제 React 컴포넌트의 탭·검색·원문·재시도·요청 경합 테스트로 구성한다. 실제 모델 호출은 테스트와 분리한 합성 평가로 기록한다. 모바일 배치와 브라우저 고유 dialog·포커스 동작은 실제 브라우저에서 별도로 확인해야 한다.

## 시간 기록과 반복 평가

새 체크포인트는 시작·완료 시각, 최초 대기 시간(queue_ms), 호출별 stage·소요시간(duration_ms)·확인된 사용량을 저장한다. 호출 시간에는 워커의 실행 권한 확인 등 호출 경계의 부가 시간이 포함될 수 있으며 순수 모델 계산 시간으로 해석하지 않는다. 실패한 호출도 경과시간과 오류를 기록하지만 응답을 받지 못한 사용량은 알 수 없다. 재개 시 이미 저장된 호출·사용량은 중복 집계하지 않는다.

- `node scripts/evaluate-summary.mjs`: 기본 합성 세션 평가. 결과는 output/summary-policy-v2/synthetic-evaluation.json.
- `node scripts/evaluate-summary-suite.mjs`: 검색어 오분류와 후속 해결·별도 보류 사례를 실제 모델로 평가한다.
- `--source-run <Run ID>`: 완료된 기존 Run을 읽어 비교 요약을 로컬 파일에만 생성한다. DB Run·요약은 갱신하지 않는다.
- `--expectations <JSON 파일>`: 해당 Run 전용 정답 참조·상태 라벨을 비교한다. evals/summary-policy-v2/existing-run-expectations.json은 기존 22개 이벤트 사례 전용 라벨이며 제품 분류 규칙이 아니다.

평가 결과의 통과는 명시된 참조·귀속·상태 라벨 검사와 모델 검토를 통과했다는 뜻이다. 단일 사례의 일반적인 정확도나 객관적인 의미 진실성으로 표현하지 않는다.
