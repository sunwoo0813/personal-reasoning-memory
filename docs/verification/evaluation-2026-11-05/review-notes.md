## 원문과 출력의 대조 검토

아래는 보조 모델 점수나 독립적인 사람 평가가 아니라, 이번 실행의 출력과 원문을 직접 대조한 검토이다. 세부 객체와 인용은 `manual-review.json`에 보존했다.

- **미해결 질문 자동 점수의 한계:** 고정 문구 기준은 2/6(33.3%)였지만, 복합 발언 사례 두 번의 “비용 제한은 어떻게 잡으면 좋을까?”는 “분석 비용 한도 미정”과 같은 미해결 사안을 표현한다. 이 두 출력을 동등한 표현으로 인정하면 4/6(66.7%)이다. 이것은 사후 대조 판정이며 사전 고정 점수와 구분한다. 나머지는 기본 사례 실패 1회와 백업 복구 시간 미확인 대신 복구 시험 방법만 남긴 사례다.
- **없는 미해결 질문 생성:** topic_switch #2는 “접근 권한 논의는 마칠게”를 “미해결 여부”로 추출했다. 논의 종료를 미해결로 바꾼 잘못된 해석이다.
- **부당한 모순 판정:** long_body #1은 “배경만으로 결정을 추론하지 말라”는 주의 문구와 사용자의 명시적 선택을 모순으로 연결했다. 사용자가 계약 조건을 읽은 뒤 선택한 것과 충돌하지 않는다.
- **가격 차이와 논리적 모순의 혼동:** reversal #2는 A/B의 가격 차이와 초기 A 선택을 모순의 근거로 삼았다. 단순한 비용 차이만으로 기존 선택이 논리적으로 모순되는 것은 아니다.
- **핵심 내용이 빠진 카드:** topic_switch #2의 일부 결정 카드는 “명시적으로 내린 적용 범위 결정”처럼 일반적으로 표현하고 실제 서버·DB 범위는 인용문에만 남겼다. 이번 결정 회수 점수는 원문 연결 기준이므로 이러한 표시 품질 문제를 포착하지 못한다.

## 다음 개선 순서

1. 발화 주체가 섞인 객체의 교정·분리와 제한된 재시도를 추가하되, 검증을 통과하지 못한 결과를 그대로 저장하지 않는다. 한 객체의 오류가 세션 전체 결과를 잃게 하는 현상을 줄인다.
2. 미완료 응답의 `status`·중단 사유·단계·토큰 사용량을 기록하고 원인에 맞는 제한된 재시도를 적용한다. 이번 미완료 응답의 구체적인 사유는 현재 로그에 남아 있지 않아 단정할 수 없다.
3. `contradiction`, `open_question`의 정의와 금지 예제를 명확히 하고 원문이 해당 해석을 실제로 뒷받침하는지 별도 검증한다.
4. 같은 개발용 사례를 개선에 사용한 뒤에는 새로 만든 독립 사례와 동의받은 실제 로그로 재평가한다. 이번 8개 합성 시나리오 결과를 실사용 전체 정확도로 일반화하지 않는다.
