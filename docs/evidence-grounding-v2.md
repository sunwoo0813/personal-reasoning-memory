# Evidence Grounding v2

## 적용 범위

근거 지정·검증·국소 교정만 변경한다. Reasoning Object의 type, speaker, 사용자 결정, 가설, Open Question 분류 정책과 purpose-v2 분할은 유지한다. 외부 저장 형식은 `extraction-v1`, 근거 방식은 체크포인트의 `grounding.version = evidence-v2`로 구분한다.

## 1. 확인한 기존 실패

2026-11-19 EP01은 3회 모두 거부됐다. 모델은 E16.response의 `합리적이야.`를 세 번 모두 `합리적이다.`로 바꿨고, 마지막에는 E19.question의 `메인 데이터`에서 공백을 삭제했다. 첫 응답에는 빈 evidence 배열도 2개 있었다. 기존 검증기의 거부는 올바른 동작이었다.

기존 교정은 일부 인용 오류 때문에 Episode 전체를 재생성했다. 정상 객체도 바뀌면서 같은 오류가 반복되고 새 오류가 추가됐다. 당시 원본 결과·후보·평가 기록은 변경하지 않는다.

## 2. 대안 비교와 선택

| 방식 | 장점 | 위험 | 결정 |
| --- | --- | --- | --- |
| 모델이 인용문 직접 생성 | 세밀한 인용 가능 | 어미·공백·문장부호를 재작성 | legacy-v1 호환 경로로 유지 |
| 모델이 시작·종료 숫자 계산 | 원문에서 잘라낼 수 있음 | UTF-16·이모지·반복 문장의 위치 계산 오류 | 채택하지 않음 |
| 코드가 원문 구간에 ID 부여, 모델은 선택 | 원문·위치를 코드로 고정 | 존재하지만 무관한 구간 선택 가능 | 채택하고 별도 관련성 검토 추가 |

## 3. 원문 근거 목록과 위치 단위

`buildEvidenceCatalog()`는 이벤트 순서를 유지하며 question/response/text/query를 읽는다. 원래 문단 경계를 우선하고, 긴 문단은 줄·문장 경계 또는 최대 480 UTF-16 code units로 나눈다. 공백뿐인 구간은 근거로 만들지 않는다. 저장할 인용을 의역·정규화·trim하지 않는다.

각 구간은 evidence_id, event_id, field, start, end, offset_unit, quote를 가진다. `[start, end)`는 JavaScript `String.slice()`의 **UTF-16 code unit** 기준이다. Unicode code point나 UTF-8 byte 위치가 아니다. 서로게이트 쌍 중간에서 자르지 않는다. 동일한 문장도 위치가 다르면 별도 ID를 부여한다. ID의 유효 범위는 해당 Episode의 근거 목록이다.

모델의 evidence 출력은 `{ evidence_id }`뿐이다. 모델이 쓴 event_id·field·quote·위치를 받아 승인하지 않는다. 복원 시 이벤트/필드 존재, 정수 위치·범위·비어 있지 않은 원문, `slice()` 결과와 quote의 완전 일치를 검사한다. 기존 `validateObjects()`의 부분 문자열·발화 주체·사용자 결정 검증도 유지한다.

기존 화자 규칙과 동일하게 질문은 user, 응답은 assistant, 검색은 user, 웹 본문은 source 근거로 제한하는 출력 스키마도 사용한다. decision은 기존처럼 user만 가능하다. unknown은 기존 허용 범위를 유지한다. 430개 이하의 목록은 화자별 ID enum을 사용하고, 더 큰 목록은 단일 ID enum과 런타임 검증을 사용한다. API의 enum 용량을 넘기지 않도록 최대 850개 근거 구간을 허용하며, 초과하면 원문을 자르지 않고 명시적으로 실패한다. 관련 제한은 [OpenAI Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs)의 enum 한도를 따른다.

근거 목록과 검토된 객체는 키 순서에 독립적인 SHA-256으로 연결한다. PostgreSQL jsonb의 키 재배열에도 체크포인트를 재개할 수 있고, 검토 이후 text·evidence 변경은 거부한다.

## 4. 문자열 일치와 관련성 검토의 구분

문자열 일치만으로 그 해석이 옳다고 판단하지 않는다. 구조 검증을 통과한 후보를 별도 `review_evidence_grounding` 호출에 전달한다. 선택 구간과 같은 필드의 앞뒤 구간을 보여주고, 부정·조건·질문/단정·발화 주체·무관한 근거에서 도출한 결론을 확인한다.

- supported: 모델이 해당 text와 선택 근거의 관련성을 지지한 판단. `grounding_review.status = model_supported`로 기록한다.
- unsupported / uncertain: 정상 객체로 수락하지 않고 국소 교정 대상으로 남긴다.
- `semantic_verification = not_verified`: 모델 검토 후에도 유지한다. 의미적 진실·인과관계·사람 검토가 완료됐다고 표시하지 않는다.

이 검토는 가설/Open Question 분류를 개선하는 재분류기가 아니다. 원문이 객체의 주장을 지지하는지만 확인한다. 검토 모델의 오판과 제한된 앞뒤 문맥의 한계는 남는다.

질문을 기록하는 객체는 실제 사용자 질문 자체로 지지할 수 있으며 답변이 있어야 하는 것은 아니다. 가설을 기록한 객체도 실제 가설 제시를 근거로 삼으며 가설의 진실성까지 요구하지 않는다. 반대로 원문에 없던 다른 질문이나 확정 결정을 주장하면 거부한다. 초기 실험에서 이 차이를 잘못 판단한 사례가 있어 검토 지침에 명시했다.

## 5. 국소 교정과 상태

objects 배열 누락/100개 초과처럼 객체를 특정할 수 없는 출력 형식 오류만 전체 형식을 추가 1회 요청한다. 존재하지 않는 ID, 빈 근거, 발화 주체 불일치, 사용자 결정 근거, 지지되지 않는 해석은 객체 번호별로 기록한다.

통과한 객체는 고정한다. `repair_evidence_objects`에는 실패한 슬롯만 보내고 대상 번호의 누락·중복·순서 변경·정상 슬롯 변경을 거부한다. 국소 교정은 최대 2라운드, 관련성 검토의 형식 수정은 검토별 추가 1회다. 마지막에는 전체 객체를 다시 검사한다.

하나라도 미해결이면 Episode는 failed다. 통과 후보는 진단에 남기지만 accepted_count는 0이며 부분 성공을 complete로 표시하지 않는다. 모든 후보가 필수 검증을 통과한 경우에만 완전한 extraction 체크포인트를 만든다. 실패 후보를 삭제하고 성공으로 처리하는 경로는 없다.

## 6. DB·체크포인트 호환성

DB 스키마는 변경하지 않는다. `analysis_steps`의 기존 extraction JSON에 grounding_audit를 기록하고, 성공 시에만 완전한 objects + grounding 결과로 바꾼다. 감사에는 후보, 통과·거부 구분, 오류 코드, 시도별 응답과 확인된 사용량이 들어간다. 기존 Run·체크포인트는 변경하지 않는다.

원문 위치·ID·모델 관련성 검토는 JSON 체크포인트에 보존한다. 기존 `object_evidence_links`에는 event_id/field/quote를 그대로 저장한다. quote_matched의 의미는 엄격한 원문 일치로 유지한다. `prm_finish_analysis_run()`의 트랜잭션, 연속 이벤트 배정, 원문 부분 문자열 검증은 변경하지 않는다.

완성된 구 방식 체크포인트는 구 방식으로 재개한다. v2의 완성 체크포인트는 입력·근거 목록·검토 결과 해시도 확인하며 재생성·재저장하지 않는다. 미완성 v2 감사는 정상 결과가 아니며, 자동 재개로 교정 예산을 초기화하지 않는다. 중단된 해당 Episode는 새 Run에서 다시 실행해야 한다. 이미 완성된 다른 Episode의 체크포인트는 유지한다.

complete/failed Run 상태를 유지하고 partial complete는 추가하지 않는다. 앞 Episode 체크포인트가 있어도 뒤에서 실패하면 Run 전체는 failed다. Reasoning Object의 최종 DB 공개는 기존 finish RPC를 통과했을 때만 이뤄진다.

## 7. 반복 평가

```sh
npm test
npm run build
node scripts/evaluate-grounding-v2.mjs output/evidence-grounding-v2-new-check 3
```

기존 22개 스냅샷, 확정된 E01–E19 / E20–E22, gpt-5-mini로 평가한다. 반복마다 새 로컬 Run을 만들고 앞 반복의 추출 결과·체크포인트를 재사용하지 않는다. DB는 읽기 전용이다. 기존 세션·이벤트·본문·Run·결과의 전후 상태와 분석 코드 해시를 비교한다. 출력 경로는 새 디렉터리여야 한다.

후보 수, 최종 검증 통과/미해결 수, 전체 Run 수락 수, 교정 횟수, 오류 발생 횟수, 토큰 사용량, 실행 시간, E19 user/decision 회수를 구분한다. 오류 발생 횟수는 동일 후보의 반복 오류를 포함하므로 고유 실패 후보 수와 다르다. 과거 구 방식 전체 실행 1회는 역사적 비교이며 일반적인 완료율의 모집단은 아니다.

동일 세션의 작은 반복 표본, 모델 검토 오판, 인용 구간의 입도, 추가 검토 비용·지연, 의미적 분류의 잔여 오류를 함께 보고한다. 단일 성공이나 인용 일치 100%를 의미적 진실·일반적인 안정성의 증명으로 해석하지 않는다.

## 8. 2026-11-20 결과

최종 코드로 고정한 3회 반복 중 2회가 완료됐다. 첫 반복은 EP01 14개 + EP02 10개, 세 번째 반복은 13개 + 12개를 수락했다. 두 번째 반복은 EP01 15개 중 14개가 검증됐지만, 1개가 근거 관련성을 끝내 통과하지 못해 전체를 실패 처리했고 EP02는 실행하지 않았다. 실패 Run의 통과 후보도 정상 결과로 합산하지 않았다.

완료된 두 Run의 49개 객체·101개 근거는 원문 위치와 정확히 일치했다. 두 Run 모두 E19의 명시적 저장소 채택·기각 결정을 회수했다. 전후 DB 상태와 평가 중 코드 해시가 일치했다. 원문 인용 문자열을 바꾸는 문제는 관찰되지 않았으나, 존재하는 잘못된 근거를 선택하는 문제는 남았다.

최종 반복의 교정 중 중복 ID 선택 5회와 관련성 불확실 5회가 기록됐다. 이들은 반복 오류 발생 수이며 고유 객체 수가 아니다. 실패한 하나의 Run은 사용자 최종 결정 대신 이전의 우려·대안 검토 발언을 계속 근거로 선택했다. 이를 허용해 완료율을 높이지 않았다.

초기 개발 실험 1/3 완료와 실패 이력도 별도 경로에 보존했다. 최종 결과는 [반복 평가 보고서](../output/evidence-grounding-v2-final-2026-11-20/report.md), 원시 응답·감사·사용량은 같은 디렉터리의 JSON/JSONL을 참조한다. 구 방식의 같은 2개 구간 전체 실행은 과거 1회 실패였다. 서로 다른 표본 크기·실행 시점의 관찰이므로 일반적인 완료율 향상으로 단정하지 않는다.
